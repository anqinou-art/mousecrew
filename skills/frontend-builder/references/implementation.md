# 实现配方：把做过的坑转成可复用行为

按当前改动选读。以下做法用于实现与复核，不要求所有产品包含全部功能；既定产品范围与接口契约优先。

## 通用页面与应用基础

- 优先复用既有组件、路由、数据层与依赖；没有项目时建立清楚的小型结构，避免为简单页面引入多套状态库。实际文案服务用户任务，不用技术说明或无来源营销词填空。
- 导航处理进入、返回、刷新和找不到页面；需要深链接时验证直接进入详情的行为。列表筛选与返回位置按产品约定保留，不能只从首页点击时正常。
- 表单字段有可理解的标签，前端即时校验与服务端规则一致；错误贴近对应字段，保留可恢复的输入。提交中防重复，成功反馈基于实际结果；破坏性动作按风险提供确认或撤销。
- 使用平台语义控件；键盘可操作、焦点可见，弹层打开/关闭有合理焦点去向。不只靠颜色表达状态，按需支持文本缩放和减少动态效果的系统偏好。
- 将外部文本、Markdown、富文本和链接当不可信输入；按内容类型转义或消毒，限制危险 URL 协议，不直接执行用户内容或放开原生桥接权限。Web 会话按实际架构处理 Cookie、安全存储和跨站请求保护。
- 按目标设备与数据规模控制首屏资源、图片尺寸、渲染次数和列表开销；记录可复现的慢场景后定向优化。公开内容站按需求设置页面标题、描述、语义结构和索引策略，不默认给私有应用开放收录。
- 承诺 PWA 能力时核 manifest、安装条件、缓存策略与离线边界；缓存变更同步资源版本，验证更新后能拿到新内容。敏感响应不进入公共缓存，离线写入如未实现就明确不可用，不伪装成功。

## 消息、流式与历史

- 消息 identity 稳定；不要在渲染或 computed property 中反复生成 UUID。格式化器、图片解码等昂贵工作缓存或预计算，I/O 移出渲染热路径。
- 成批事件合并后再更新列表；避免逐条通知造成重绘和滚动动画排队。选择能代表实际语义的变化信号，不把“监听整个数组”当通用性能处方。
- 初次进入看最新；用户上翻后保留锚点，新消息给回底入口。加载旧页前后保持所读内容的位置，键盘、图片补齐高度和流式增量不应造成跳动。
- 区分增量、最终回复与终止/失败事件；按真实协议完成同一条消息，避免 delta 后再追加一遍完整 reply。切会话和重载时清理属于旧轮的临时标志。
- 历史分页的游标与 hasMore 依据接口原始页或明确分页字段；展示去重不能缩短原始页后误判到底。搜索到旧消息应按契约有界定位，不无限扫描。
- 重连补读和实时事件有先后保护；旧请求不得覆盖新事件。状态离开忙态不必然成功，失败/打断应保留已到达的内容并显示真实结果。

## 输入、附件与草稿

- 多行输入要处理中文输入法组合态，避免选字时发送；键盘快捷键按平台与用户约定。
- 草稿按会话/窗口隔离，正文与待发附件一起归属。发起发送时捕获目标和本次快照；成功只清掉已发送内容，失败保留，切换后不串窗。
- 选图、拖拽、粘贴走同一受控入口；普通文字粘贴仍保持原生行为。预览可移除，空正文是否合法由接口决定。
- 显示缩略图与上传原件分开：若协议要求原字节就不擅自压缩；确需上传压缩时在后台做，明确质量/尺寸策略。大图解码和编码不堵界面。
- 附件和正文是独立字段，使用结构化 metadata；只在有迁移要求时兼容旧文本标记。无文字消息去重必须包含稳定消息/附件身份。
- 受保护图片/文件沿鉴权入口读取，限制到协议允许的来源与路径。对象 URL、读取任务及时释放；旧会话迟到的图片不填进新会话。
- 发送锁应在重复事件可进入前生效；UI disabled 是表现，不是唯一防重机制。失败显示服务端可理解的原因，不在前端发明另一套大小/数量限额。

## 状态、设置与内容确认

- 每个加载、取消、错误出口都能结束本次 loading；用操作 identity 防止旧任务 finally 清掉新任务状态。清理定时器、事件订阅与过期读，页面切换后不留重复消费者。
- 写入只有获得实际成功结果才显示成功。涉及“上传再保存设置”等多步操作，不能把第一步完成写成整件事完成。
- 个性化设置按既定 scope 存储；版本升级保留已有键和用户选择，默认值只用于未设置/非法输入，不能顺手覆盖。
- 审批、已读、版本确认以服务端为准；需要确认所见文档时绑定显示的版本/hash，冲突后刷新，不替用户确认没看见的新版本。其他操作是否采用版本机制由其合同决定。
- 折叠和滚动等本地浏览状态尽量在内容刷新时保留；同一进程内保活不能当作跨重启恢复。

## 视觉、菜单与嵌入面板

- 毛玻璃先辨认哪一层已提供 material/blur；子元素叠加填充与描边即可时，不再套第二层模糊。不同承载层可用不同参数，不做全 App 一次替换。
- 菜单定位绑定触发元素并约束到当前窗口；点外部、Escape、焦点返回与菜单选择的关闭行为一致。固定 top/right 数值需要对应的容器与坐标系，不能照搬到不同缩放、滚动或原生环境。
- 装饰边框与角贴分层；背景、图片、长链接、表格和代码的溢出各自处理。桌面分栏有最小可用宽度，窄窗有明确收起策略。
- WebView/原生浏览器面板有独立生命周期与坐标系；窗口缩放、侧栏、分隔线、弹窗和拖动时同步其矩形/可见性，避免原生层盖住菜单。是否保活以产品约定为准。
- 父级横扫/拖动手势不能吞掉按钮轻微移动、阅读翻页或选字。检查真实设备的安全区；模拟器成功不覆盖真机差异。

## 鉴权与设备运行

- 复用统一 API 客户端，凭证只给可信目标，第三方请求不携带；REST、SSE、上传、受保护图片都纳入真实路径核查。
- 按平台用合适的安全存储。Apple 平台 Keychain 失败需定位签名、entitlement、OSStatus，不回退明文，不靠重置用户钥匙串消除症状。
- WebView 换 cookie 的项目保留批准的桥接方式，不能把 token 注入页面脚本来图省事。重新登录/轮换后处理仍持旧请求的长连接。
- 安全验证要看请求是否实际经过鉴权路径；接口 200、没有错误日志、读到缓存都不足以单独证明凭证有效。
- 校验环境必须代表所声称的结论：无签名隔离包可看布局，不能证明日用签名包的 Keychain 正常；GUI 假数据可验组件，不能证明真实模型收到附件。

## 选最小有效证据

布局变化看代表性视口；接口映射看请求/响应；异步竞态用定向测试；签名/权限/原生桥接用相应运行环境。检查已有实现者证据是否仍适用于当前代码，不为“独立”重复整套测试。

给用户保留可用入口，交代样稿与成品的区别、改了哪里、哪些仍待设备体验。没有运行过的路径写未验，不能用测试数量代替证据范围。
