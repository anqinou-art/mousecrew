# 合同（第 8 步）

每张单一份。每一栏都要填；填不出来的那栏，说明你还没准备好开这张单。

## 开单前先过六问（不过就不开）

1. **它真的缺吗？** 读代码或实测证明它现在没有。别凭文档、别凭印象。
2. **整条路走过了吗？** 新信号 / 新字段从产生到被用的每一站都 grep 一遍，路上每个文件都进准改列表。两头都要走：数从哪来、往哪推，**还有现在谁在读它**（改了形状，旧的读者会不会读错）。
3. **照这份做出来起得来吗？** 在脑子里（能跑就真跑）从头做一遍：启动会不会被拒、新东西有没有调用方、测试能不能在准改范围内写。
4. **要不要加依赖、改配置格式？** 要的话写进准改列表并说版本策略（锁精确版本），或者明说不准、给另一条路。
5. **你实测过哪些、没实测哪些？** 实测过的写「我在 X 上跑过：……」；没实测的全放进「我没核过」那栏。⛔ 不用肯定句递一个没核过的东西。
6. **你加的约束比项目规矩严吗？** 严的会逼出复制。

## 判大小

「大」= 三条中一条：① 改别人怎么干活（规矩 / 流程 / 任何 agent 的说明书）② 花人的东西（钱、人的时间、不可逆的数据格式）③ 一只一天做不完。大的交给人拍，小的直接派。**小活也开单**——单是审计闸门的钥匙，不开单就是绕过审计。

**没真发生过的 bug 不开单。** 判据是「发生过吗」，不是「严不严重」。

## 正文骨架

```
【是什么】一两句：给谁用、解决什么。出处（人的原话 / 总纲）。
功能地图：<是地图里的哪一项>
接在 <仓库> <分支 / 提交号> 上。

【共同验收】全量测试全过并贴汇总行；<语言 / 提交署名 / 脱敏要求>。

【准改的文件】逐个列。要动别的先停下来在单上问。
  列表下面贴一行「我 grep 了什么」：这次要改的每个函数名 / 字段名 / 接口路径都 grep 一遍，
  命中的文件要么进列表，要么写一句为什么不用改。

【要交的】写要求的现象，⛔ 不写步骤。
  每一处「只能有一个写入者 / 不许两份」的地方点名写出来，并指出现有那份在哪。

【验收】
  单测：<红绿两边都要验的边界>
  现场验：<真跑什么、贴什么>。考「读没读到」只用被测对象独有的内容（编一个只有它知道的名字 / 数）。

【我没核过、你实测后定的】逐条。拿不准的写成停点：「……不是这样就停下来在单上问」。

【不做】边界外的、下一张单的。

【收口】过审合并后告诉架构一句。
```

## 为什么这么写（踩过的坑）

- **只写现象不写步骤**：合同里写了步骤，施工的人会照做，哪怕步骤和要求打架（写了「先写临时文件再改名」，而改名会静默覆盖同名文件，和「同名不覆盖」直接冲突）。
- **准改文件要贴 grep**：你列文件靠的是脑子里那张图，那张图永远比代码少几条边。被施工的人停下来问住的文件，grep 一下都在那儿。但 grep 只能搜你想得到的词，所以还要有停点。
- **诊断是猜的就标成猜的**：你把猜的病因写成肯定句，施工的人就照着修——修得一点不错，错的是你递过去的那张图。
- **停点比六问更管用**：六问是你对自己的检查，会漏；停点是把检查分给站在现场的人。代价要认：停下来问花的是他们的时间。

## 碰到这些要点名写

- **隐私 / 凭据**：不进日志、事件、错误信息、工具输出、文件；报错只说「取不到」。验收里造一个假凭据串，全文 grep 0 命中。
- **两套真相**：已有一份规则 / 一条推送 / 一个写入者的，写明「⛔ 不另写一份」，指出现有那份在哪。
- **冒充**：请求别家服务时 ⛔ 不冒充别家的客户端身份，除非实测证明必须（并告诉人）。

## 派出去以后

- 施工的人停下来问 = 合同有洞或你预留的停点。当场裁，裁定落在单上，群里一句人话；别的在飞的单有同样的洞，一起补。
- 一张单评估一天做不完，拆开；拆的时候写清原单留哪段、新单接哪段、谁依赖谁。
