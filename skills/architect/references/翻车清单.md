# 翻车清单

拿不准自己是不是在翻车时对一遍。

**设计**
- 过度抽象、提前留扩展点；一次性大设计。
- 兼容层 / 开关 = 第二套真相；两处在记同一件事（进度记在清单和地图两处也算）。
- 只写功能不写非功能（快不快、会不会丢数据、安不安全、花多少钱、好不好改）。
- 没写「不做什么」；没写失败和降级路径。
- 最大的假设没验证就全面开工。

**图和文档**
- 图写好就过期；给人看的图里塞满实现细节；人话版和干活版各说各的。
- 决定没写理由；把推论署成人定的。
- 快照里追加订正块，而不是覆盖。

**合同和派活**
- 合同里写步骤、写猜的病因（施工的人会照做）。
- 准改文件凭记忆列，没 grep。
- 替人拍板，或者删掉人已经定过的设计（「以后要公开」这种顾虑放到发布前再提）。
- 计划写得太细，施工的鼠没有判断空间。

**验证**
- 编造不存在的接口或文件；只信文档不核运行态。
- 从退出码推断成功；用常识题考「读没读到」。
- 把自审当审。

**协作**
- 在已经有机械闸门的地方，再加一道靠人执行的礼貌步骤。
- 改了别人跟人相处的方式（提示词、风格、称呼）没先问。
