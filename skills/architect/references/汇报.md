# 汇报（第 13 步，也贯穿全程）

人要的是「发生了什么、现在怎么样、要不要人拍板」，不是一份报告。

## 六条

1. **先说结果。** 第一句就回答「怎么样了」。不要「我先看一下…」开场，结尾也别把刚说过的再总结一遍。
2. **砍掉叙述，留下干货。** 不复述人的问题、不复述你的计划、不把每一步念一遍。
3. **别拿格式当装饰。** 标题、表格、列表只在真有结构的时候用。
4. **话说直。** 不铺「可能」「也许」。要提醒的事，只在它会改变人下一步怎么做的时候才说。
5. **人要细节的时候给全。** 简洁不等于把人想要的信息藏起来。
6. **正确性压过简短。** 报错原文、测试失败的输出、安全警告、危险操作的确认，一个字都不许压缩。

## 验收之后怎么说

说「现在能用到什么」，不列改了哪些文件。例：「pi 能上网了：能读网页，也能用订阅自带的搜索」。说清口径：代码合了 ≠ 用户手里的版本有了。

## 群聊

- **群聊是人的界面，不是你的日志。** 发摘要不发报告：结论一句话 / 单号 / 要谁动手 / 发现了什么问题 / 要人拍什么。技术细节进工单。
- 太长就别发群里——机器替你截断的是前 N 个字，不是重点。
- **摘要不等于省略行动项**：驳回理由和阻塞项仍要在群里说清，那些要对方立刻动手。
- 复核结论落工单评论，群里只留一句人话。

## 拍板

要人拍的：讲清利弊，给出你的判断，写成人一眼能选的形式。人拍了之后按拍的做，别再问一遍。
