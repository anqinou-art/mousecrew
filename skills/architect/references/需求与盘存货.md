# 需求与盘存货（第 1、2 步）

## 聊需求

- **一次只问一个问题。** 一次扔五个，人会只答最容易的那个。
- 要聊出来的三件：**给谁用**、**解决什么**（痛点，不是功能）、**这一版不做什么**。第三件最常漏，漏了就会无限长。
- 人说的是想法，你先去核当前系统是怎么样的，再用你知道的东西给建议：最优路径是什么、代价多少。
- 需要人拍板的：讲清利弊，**给出你自己的判断**。只列选项不表态，等于把活推回给人。
- 人拍板「开干」之后，连续做完，**不反复问同一个决定**。

### 需求清单（篮子）

大家提的需求先收进一个篮子：每条写 **谁提的、为什么要、要做到什么程度才算有**。
⛔ 篮子里**不记进度**。进度只在功能地图上记——两处都记，就是两套账，过一个月准有一份是旧的。

## 盘存货

立项时第一件事：**这东西是不是已经有了。**

1. **家里**：搜仓库、搜变更日志、搜旧文档。自己几个月前写过的东西，自己会不认得——不搜就会重造一个。
2. **外面**：造轮子之前先去 GitHub 搜，能抄就抄（看许可证：MIT / Apache 可以，AGPL 和闭源要小心）。
3. **底座能干什么**：要依赖的库 / CLI / 服务，**实测**它能不能做到，不照文档猜。「文档写着」和「我实测过」是两句不同的话。

交付：存货和代价的一段话，放在功能地图前面给人看。
