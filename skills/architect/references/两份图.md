# 两份图（第 4、6 步）

一份给人确认，一份给鼠干活。**顺序是一道关**：人话版人点头了，才画干活版；干活版齐了，才开单。

用 Mermaid 画（纯文字，GitHub / VS Code / 大多数 markdown 预览直接出图，鼠也能改）。⛔ 别用 Mermaid 的 C4 语法（还是实验性的，不能自动布局）。

## 人话版（给人确认）

回答「这些东西怎么连起来」。

- **框**：每个框一句话说它干嘛。⛔ 不出现文件名、接口、字段。
- **线**：线上写**流过去的是什么**（「聊天记录」「派活」「弹卡片问你」），不写「调用」。
- **框数**：一张图 5–7 个框。
  - **外部的东西不算数**：人、第三方服务这种不归我们管的，画成圆框放边上。
  - **装不下就分层，别硬塞**：总图的每个框都能「点开」成一张同样是人话的小图。人看总图确认大方向，关心哪块点开哪块。
  - 一张图想讲所有线，就会像耳机线缠在一起。
- **标状态**：每个框标「已经在跑 / 在做 / 只是想法」，免得人以为都做好了。

例：

```mermaid
flowchart LR
  you(["你"])
  app["App 窗口<br/>聊天 · 看板"]
  hub["管家<br/>收话、派给谁、排队"]
  worker["干活的 agent"]
  ext(["外部服务"])
  you -- "说话、点允许" --> app
  app -- "你的话" --> hub
  hub -- "派活（忙就等）" --> worker
  worker -- "回话、交活" --> hub
  worker <-- "想问题" --> ext
```

## 干活版（给鼠）

在人话版每个框里展开，每块写清：

| 栏 | 写什么 |
|---|---|
| 对应 | 人话版里的哪个框 |
| 管什么 / 不管什么 | 边界，后一半最重要 |
| 在哪 | 文件 / 目录 |
| 吃什么、吐什么 | 输入输出的形状 |
| 状态归谁 | 每份状态、每类数据**只有一个写入者**，点名写出来 |
| 谁调它、它调谁 | 依赖只能单向，A 引 B 就不许 B 引 A |
| 出错怎么办 | 失败和降级路径（这一栏最常漏） |
| 最没把握的地方 | 标出来，对应 `风险与小实验.md` |

图：总图用 flowchart；一次请求怎么走用 sequenceDiagram；有状态机的用 stateDiagram。

每节标题下盖核实戳：`> 🗓 核实 YYYY-MM-DD｜盯：<路径>`。盯的东西变了，这节就该重核（见 `维护.md`）。

## 两份图不许各说各的

人话版的每个框必须能在干活版里找到对应的块；干活版多出来的块，要么归进某个框，要么说明为什么人不用关心。
